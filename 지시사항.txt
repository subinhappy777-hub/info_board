T04-1. 오늘의 진짜 관광정보판 — 데이터가 안 올 때
활용 API: 한국관광공사_국문 관광정보 서비스_GW

개발 형태: 무로그인 공개 웹 애플리케이션

예상 작업시간: 6~7시간 (실제 날짜별 데이터 수집 대기 시간 제외)
1. 왜 이 프로젝트를 하는가?
실제 데이터 서비스는 정보를 정상적으로 가져오는 것만큼이나, 데이터가 늦게 도착하거나 잘못된 형식으로 전달될 때 어떻게 대응하는지가 중요합니다.

이번 프로젝트에서는 한국관광공사 국문 관광정보 서비스 API를 활용하여 축제 정보를 수집하고, 매일 데이터의 변화를 기록합니다.

API 요청에 실패하더라도 마지막으로 정상 수집한 데이터를 보존하고, 사용자에게 현재 데이터의 상태를 정확하게 알려주는 시스템을 만듭니다.

핵심은 데이터를 보여주는 것뿐만 아니라, 데이터가 들어오지 않는 상황에서도 신뢰할 수 있는 정보를 제공하는 것입니다.
2. 프로젝트 목표
한국관광공사 국문 관광정보 서비스 API를 활용하여 다음 기능을 구현합니다.
1. 실제 관광정보 API에서 축제 정보를 가져옵니다.
2. 매일 동일한 조건으로 데이터를 수집하고 날짜별 기록을 저장합니다.
3. 어제와 오늘의 관광정보를 비교하여 변화를 보여줍니다.
4. API 호출에 실패하더라도 마지막 정상 데이터를 보존합니다.
5. 데이터 수집 상태와 오류 상황을 사용자에게 명확하게 표시합니다.
3. 사용할 데이터
데이터 출처: 한국관광공사_국문 관광정보 서비스_GW
- 제공 기관: 한국관광공사
- 제공 플랫폼: 공공데이터포털
- 데이터 형식: JSON 또는 XML
- 활용 API: 축제 정보 조회 API
주요 활용 인터페이스:
- searchFestival2: 축제 정보 조회
- detailCommon2: 관광정보 공통 상세 조회
- detailIntro2: 축제 상세 정보 조회
기본 API 주소:
https://apis.data.go.kr/B551011/KorService2/searchFestival2


주요 수집 항목:
- contentId: 관광정보 고유 ID
- title: 축제명
- eventStartDate: 축제 시작일
- eventEndDate: 축제 종료일
- addr1: 축제 주소
- modifiedtime: 관광정보 최종 수정 시각
- collectedAt: 실제 데이터 수집 시각
※ collectedAt은 API가 제공하는 값이 아니라 직접 기록하는 수집 시각입니다.
4. 핵심 구현 기능
① 실제 관광정보 수집
- 한국관광공사 API를 통해 실제 축제 정보를 가져옵니다.
- 매일 동일한 검색 조건으로 데이터를 수집합니다.
- 수집된 데이터를 JSON 형태로 저장합니다.
- API 응답이 정상적으로 도착했는지 검증합니다.
② 어제와 오늘의 데이터 비교
매일 수집한 데이터를 비교하여 어떤 변화가 발생했는지 보여줍니다.

비교할 내용은 다음과 같습니다.
- 새롭게 등록된 축제
- 수정된 축제 정보
- 종료되거나 조회 결과에서 사라진 축제
- 축제 시작일까지 남은 일수(D-day) 변화
D-day는 날짜가 지나면서 자동으로 달라지는 계산상의 값이므로, 실제 관광정보 수정과 구분해서 표시해야 합니다.
③ 마지막 정상 데이터 보존
API 요청이 실패하거나 응답에 문제가 발생하면 마지막으로 정상 수집한 데이터를 유지합니다.

테스트할 오류 상황은 다음과 같습니다.
- API 서버 응답 지연
- 인증키 오류
- 일일 호출 제한 초과
- 인터넷 연결 실패
- JSON 데이터 형식 오류
이때 기존 정상 데이터를 삭제하거나 빈 데이터로 덮어쓰면 안 됩니다.

오류 발생 시 사용자에게 다음 정보를 표시합니다.
- 현재 데이터 수집 상태
- 오류 발생 원인
- 마지막 정상 수집 시각
- 현재 표시 중인 데이터가 마지막 정상 데이터라는 안내
④ 오류 상황 5종 테스트
실제 API 서버에 반복적으로 오류를 발생시키는 대신, 테스트용 오류 상황을 인위적으로 재현합니다.
오류 종류	테스트 상황	기대 결과
Timeout	API 응답이 일정 시간 이상 지연	마지막 정상 데이터 유지
인증 오류	401 또는 403 응답	인증 오류 안내
호출 제한	429 응답	호출 제한 안내
네트워크 오류	인터넷 연결 실패	연결 오류 안내
데이터 오류	JSON 형식 또는 필수 항목 누락	잘못된 응답 안내

모든 오류 상황에서 마지막 정상 데이터가 유지되는지 확인해야 합니다.
⑤ 데이터 수집 이력 보존
서로 다른 실제 날짜에 수집한 데이터를 최소 2건 이상 저장합니다.
- 첫 번째 날짜: 실제 API 데이터 수집 및 저장
- 두 번째 날짜: 실제 API 데이터 재수집 및 저장
- 두 날짜의 데이터 차이 비교
- 수집 성공 여부와 수집 시각 기록
샘플 JSON이나 오류 재현 데이터는 실제 수집 기록으로 인정하지 않습니다.
5. 웹페이지 구성
웹페이지에는 다음 영역이 포함되어야 합니다.
1. 오늘의 데이터 상태
   - 현재 데이터 수집 상태
   - 마지막 정상 수집 시각
   - 최근 수집 성공 또는 실패 여부
2. 오늘의 축제 정보
   - 축제명
   - 축제 시작일과 종료일
   - 축제 주소
   - 축제 시작일까지 남은 일수
3. 어제와 오늘의 데이터 비교
   - 신규 등록 축제
   - 수정된 축제 정보
   - 종료되거나 조회 결과에서 사라진 정보
   - D-day 변화
4. 최근 수집 이력
   - 날짜별 수집 시각
   - 수집 성공 또는 실패 여부
   - 날짜별 데이터 개수
   - 마지막 정상 데이터 기록
5. 오류 테스트
   - Timeout 재현
   - 인증 오류 재현
   - 호출 제한 재현
   - 네트워크 오류 재현
   - 데이터 형식 오류 재현
6. 데이터 저장 구조
다음과 같은 파일 구조를 권장합니다.
today-real-info/
│
├── collector/
│   └── collect.py
│
├── data/
│   ├── latest.json
│   ├── history.json
│   └── events.json
│
├── public/
│   ├── index.html
│   ├── style.css
│   └── script.js
│
├── .env
├── .gitignore
└── README.md


각 파일의 역할은 다음과 같습니다.
- latest.json: 가장 최근 정상 수집 데이터
- history.json: 날짜별 실제 수집 기록
- events.json: 오류 발생 및 복구 기록
- collect.py: API 호출 및 데이터 수집
- index.html: 웹페이지 구조
- style.css: 웹페이지 디자인
- script.js: 데이터 표시 및 비교
API 인증키는 .env에 보관하고 GitHub에 공개하지 않습니다. 공개 웹페이지에서는 인증키를 직접 사용하지 않고, 수집된 JSON 파일을 읽어 데이터를 표시하도록 구성합니다.
7. 제출물
① 결과물 주소
- 무로그인으로 접속할 수 있는 공개 웹페이지 주소
② 소스 주소
- GitHub 저장소 주소
③ 짧은 확인 방법 4줄
다음 네 가지 내용을 작성합니다.
1. 위치: 웹페이지에서 어디로 접속해야 하는가?
2. 행동: 어떤 순서로 확인하면 되는가?
3. 통과 모습: 정상적으로 작동하면 무엇이 보여야 하는가?
4. 안 될 때 모습: 오류가 발생하면 어떤 상태가 보여야 하는가?
④ AI와 나의 판단 3줄
다음 세 가지 내용을 작성합니다.
1. AI에게 맡긴 일: API 호출 코드, JSON 데이터 처리, 화면 구성 및 오류 테스트 코드 작성.
2. 직접 판단한 일: 수집할 관광정보, 비교할 데이터, 정상 데이터 보존 기준 결정.
3. AI 제안을 따르지 않은 일: AI가 제안한 방식 중 실제 수집 기록과 샘플 데이터를 혼동하거나 기존 정상 데이터를 삭제할 수 있는 방식이 있었다면, 이를 따르지 않은 이유 작성.

9. 권장 작업 순서
단계	작업	예상 작업시간
1	API 신청 및 실제 호출 확인	1시간
2	데이터 수집 및 JSON 저장	1시간
3	마지막 정상값 및 이력 관리	1시간
4	오류 5종 재현 및 검증	1시간
5	웹페이지 화면 구현	1.5시간
6	실제 데이터 연결 및 통합 테스트	0.5~1.5시간
합계		6~7시간

※ 서로 다른 날짜의 실제 기록 2건을 만들기 위해 필요한 대기 시간은 작업시간 6~7시간에 포함되지 않습니다.

최종 목표: 한국관광공사 API에서 실제 관광정보를 수집하고, 날짜별 변화와 수집 상태를 기록하며, API 오류가 발생해도 마지막 정상 데이터를 보존하는 신뢰할 수 있는 관광정보 서비스를 완성합니다.
